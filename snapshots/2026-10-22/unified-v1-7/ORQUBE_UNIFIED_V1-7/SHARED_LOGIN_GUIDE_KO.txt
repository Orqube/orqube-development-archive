오르큐브 통합 로그인 수정본 V1.6

반영 내용
- 웹: 오르큐브·울림·갤럭시·777·오목·낚시·스카이러너의 공통 로그인 세션 연동.
- 웹: 사이트에 다시 방문하거나 다른 앱에서 브라우저로 돌아오면 로그인 상태 재확인.
- 직접 로그아웃하면 공통 세션을 해제하고 다른 게임은 다음 인증 확인/복귀 때 반영.
- 일시적인 통신 실패로 로그인 쿠키와 Firebase 로그인을 삭제하지 않음.
- 기존 Firebase 계정/닉네임/프로필과 게임 기록은 그대로 사용.

반드시 필요한 통합본 배포
이 ZIP은 소스입니다. 다운로드만으로 기존 Firebase 홈페이지가 변경되지는 않습니다.
압축을 푼 폴더에서 PowerShell을 연 뒤:
  powershell -ExecutionPolicy Bypass -File .\DEPLOY_SHARED_LOGIN.ps1
또는 순서대로:
  flutter pub get
  flutter build web --release
  firebase deploy --project orqube-576e7 --only "functions:sharedAuthToken,hosting"
Firebase CLI에 기존 프로젝트 관리자 계정으로 로그인되어 있어야 합니다.
이 배포는 다른 AI Functions, Firestore Rules, 스테이킹 컨트랙트를 배포하지 않습니다.

custom token 생성 권한 오류가 날 때만
sharedAuthToken 함수의 실제 런타임 서비스 계정에 자기 자신에 대한
Service Account Token Creator 권한이 필요할 수 있습니다.
Firebase/Google Cloud 로그에서 iam.serviceAccounts.signBlob 권한 오류를 확인한 뒤
프로젝트 관리자가 해당 함수 서비스 계정에만 설정하세요.

적용 범위와 확인 한계
같은 휴대폰/같은 브라우저의 웹 사이트들 사이에서 공통 로그인을 사용합니다.
서로 다른 브라우저, 시크릿 모드, 별도 WebView와 설치형 APK는 쿠키가 분리됩니다.
APK의 Firebase 로그인은 앱을 전환하거나 다시 실행해도 기존 기본 영구 저장을 사용합니다.
APK와 외부 브라우저 사이의 양방향 자동 로그인은 이번 웹 공통 세션과 별개이며
딥링크/네이티브 전달을 추가 구현해야 합니다. 이 수정본은 그 기능을 완료했다고 주장하지 않습니다.
브라우저 데이터 삭제, 비밀번호 변경/계정 차단, 보안상 세션 무효화 시 재로그인이 필요합니다.
서버의 공통 세션은 약 1년의 갱신 가능한 만료를 사용하며, 영구 무기한을 보장하지 않습니다.

검증
서버 로그인·갱신·단일사용 코드·대상 도메인 제한·코드 만료·로그아웃 무효화·
통신 장애 시 세션 보존에 대한 자동 검증을 수행했습니다.
이 작업 환경에는 Flutter SDK가 없어 Flutter/Android 컴파일은 실행하지 못했습니다.
실제 사용자 계정으로 다중 사이트 로그인, 모바일 복귀 동작은 배포 후 확인이 필요합니다.

사용 확인 순서
1. 배포 후 오르큐브 또는 울림에서 한 번 로그인합니다.
2. 같은 브라우저에서 galaxy.orqubic.com, omok.orqubic.com, 777.orqubic.com을 엽니다.
3. 게임에서 다른 앱으로 전환했다 돌아와 로그인 상태가 남아 있는지 확인합니다.
4. 한 사이트에서 로그아웃한 뒤 다른 게임으로 돌아와 공통 해제가 반영되는지 확인합니다.
5. 낚시/스카이러너는 도메인이 달라 자동 인증 이동이 한 차례 보일 수 있습니다.
