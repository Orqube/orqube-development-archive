ORQUBE 안심동행 V2.0 — 내 사람·모임 / 공유 대상 선택

V1.9.1 전체 기능과 확인하신 6개 언어를 유지하고 새 화면 번역을 추가한 전체 소스입니다.
APK가 아니며 실제 Flutter/실기기 검증 전 개발본입니다.

첫 화면
안전산행 / 안심귀가 / 위치 공유 / 내 사람·모임 / 로그인·내 계정 / 사용설명서

가족·친구 등록
내 사람·모임 → 사람 추가 → 내 목록에 표시할 이름, 관계(가족·친구·보호자·산행 동료), 상대 연결 ID 입력 → 초대 보내기.
상대는 별도 계정으로 로그인·이메일 인증 → 내 사람·모임 → 받은 초대 → ID 확인 후 수락.
한 번 수락하면 서로 연결됩니다. 각자 표시 이름·관계를 따로 저장합니다.
전화번호만으로 위치를 조회하거나 사용자를 찾아내지 않습니다.
빈 목록, 초대 없음, 수락 대기, 불러오기 오류를 각각 표시합니다.
상대의 초대/승인 변경은 약 15초 간격 또는 새로고침으로 확인합니다.

공유 선택
안전산행·안심귀가: 이동 시작 → 위치 공유 → 공유할 사람 체크 → 동의하고 시작.
안전산행은 각 사람별 '마지막 산행 기록 조회 허용'도 별도로 선택합니다.
실시간 대상과 수색자료 대상이 구분됩니다. 수색자료 선택은 실시간 선택한 사람 안에서만 가능합니다.
별도 '위치 공유'는 산행/귀가를 시작하지 않고 가족·친구에게 최대 30분 공유합니다.
이 화면을 떠나면 공유 종료를 시도하며 백그라운드/강제 종료 연속 공유를 보장하지 않습니다.
공유 중에는 '공유 대상 변경'으로 대상을 바꿀 수 있습니다. 모두 해제하면 현재 공유를 종료합니다.

변경과 해제
이름·관계 변경: 내 표시만 변경.
공유 중지: 그 사람을 현재 실시간/수색자료 대상에서 제외. 연결은 남음.
연결 해제: 양쪽의 위치·수색자료 접근 연결을 취소. 다시 연결하려면 새 초대·수락 필요.
초대 취소/거절: 아직 연결되지 않은 초대를 폐기.
오프라인에서는 서버 반영이 지연될 수 있고, 이미 캐시/파일/메시지로 받은 자료는 회수할 수 없습니다.
연결 해제 후 남아 있던 여러 중복 초대 연결도 함께 취소하도록 처리했습니다.

내 산행 모임
연결된 사람을 모임 이름으로 묶어 공유 대상 선택 때 한 번에 추가할 수 있습니다.
개인 계정의 공유 대상 묶음이며, 다른 사람에게 공개되는 산악회 가입/명부/모임 방이 아닙니다.
여러 참가자의 위치를 동시에 한 지도에 표시하는 산악회 전체 지도는 이번 범위에 포함되지 않았습니다.
모임 변경은 묶음을 수정합니다. 진행 중 공유 대상에 자동 반영하지 않으므로 공유 대상 변경에서 적용하세요.
모임 삭제는 묶음만 지우며 개별 연결/이미 진행 중 공유는 유지합니다.
그룹의 연결 끊긴 사람은 공유 대상 일괄 선택에서 제외됩니다. 공유 대상 상한은 한 번에 50명입니다.

기존 보호자 자료
이전 단일 이름/전화번호 설정과 승인 ID만으로 새 연결을 자동 승인하지 않습니다.
새 '사람 추가 → 상대 수락'을 한 번 진행해야 합니다. 기존 산행/오프라인 경로 기록은 유지됩니다.
이전 보호자 규칙을 그대로 두면 새 권한 선택을 우회할 수 있으므로 반드시 아래 교체를 진행하세요.

중요: 이번 버전은 Firestore 규칙 갱신이 필요합니다.
1) Firebase 콘솔에서 현재 규칙을 별도 백업합니다.
2) companionVerified 함수와 기존 safety_requests, safety_shares, hiking_search_records match 블록을 찾습니다.
3) 위 함수·세 경로 블록을 제거한 자리에 COMPANION_RULES_V20_REPLACE.txt 내용을 넣습니다.
   companion_connections와 companion_contacts 경로가 이미 있다면 중복 없이 교체합니다.
4) signedIn(), owner() 등 ORQUBE 기존 함수/다른 서비스 규칙은 유지합니다.
5) 콘솔 검사 후 게시합니다. 서버에는 이 ZIP으로 대신 게시하지 않았습니다.
전체 참고 병합본 firestore.companion.merged.rules는 사용자가 이전에 주신 전체 규칙을 기반으로 합니다.
그 이후 운영 규칙을 변경했다면 전체 병합본으로 덮어쓰지 말고 위 companion 블록만 교체하세요.
규칙이 중복되면 허용 조건이 합산되므로 이전 safety_shares/search 블록을 남겨두면 안 됩니다.
새 규칙 없이는 초대/사람 저장이 permission-denied로 실패합니다. 로그인 문제로 오해하지 마세요.

두 계정 권한 테스트(필수)
A 가족 추가 → B 받은 초대 수락 → 양쪽 연결된 사람 표시 확인.
수락 전 B가 A 위치/수색자료를 직접 읽으면 거부되어야 합니다.
연결만 수락하고 A가 공유하지 않았으면 B 위치 조회가 거부되어야 합니다.
A가 B만 실시간 대상 선택 → B 실시간 조회 허용 / B 수색자료 조회 거부 확인.
A가 B의 마지막 산행 기록도 허용 → B 수색자료 조회 허용 확인.
C 미승인 계정으로 A 자료 읽기와 다른 UID 쓰기가 모두 거부되는지 확인.
A에서 B 공유 중지 → B 실시간/수색자료 접근 거부, 연결 카드 유지 확인.
B에서 연결 해제 → 양쪽 접근 거부, 새 초대 없이는 재공유 불가 확인.
가족/친구 이름 변경, 초대 취소·거절, 모임 추가·변경·삭제를 확인.
모임에 있었지만 연결 해제된 사람은 다시 공유 대상에 들어가지 않는지 확인.
온라인/오프라인 중지와 재시도, 산행·귀가·30분 공유 각각 확인.
6개 언어 및 모바일 줄바꿈 확인. 한국어로 입력한 이름은 번역하지 않는 것이 정상입니다.
