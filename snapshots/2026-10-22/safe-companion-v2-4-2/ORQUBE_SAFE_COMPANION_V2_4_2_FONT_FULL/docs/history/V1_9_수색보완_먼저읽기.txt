ORQUBE Safe Companion V1.9 — 안전산행 수색 보완 전체 소스

V1.8.1 실시간 지도와 컴파일 오류 수정 내용을 포함합니다.
APK가 아닌 전체 Flutter 개발 소스입니다. 새 폴더에서 실행하세요.

이번 구현
1. 기기 우선 저장: 위치 좌표, 실제 GPS 관측시각, 정확도, 고도, 산행 시작/귀환 예정시간을 계정별 SharedPreferences에 저장합니다.
   같은 GPS 관측시각은 중복 저장하지 않습니다. 약 5m 이동 또는 15초 경과 시 기록합니다.
   이 기기의 계정별 최근 산행 1건, 최대 최근 10,000개 관측점을 유지합니다. 초과 삭제 건수를 표시합니다.
   새 산행 시작은 이전 기기 기록을 교체합니다. 필요한 기록을 먼저 내보내세요.
2. 재전송: 별도 자료 공유에 동의한 경우 서버 전송 대기를 기기에 보관합니다.
   앱 실행 중 약 20초마다 재시도하며 로그인 후에도 대기 작업을 다시 시도합니다.
   서버 경로는 최대 4,000개 관측점을 균등 추출하여 시작/마지막 점을 포함합니다.
   서버에 받은 시각과 GPS가 실제 관측된 시각을 구분합니다. 단순 폴링은 관측시각을 새로 만들지 않습니다.
3. 마지막 기록 조회: 실시간 지도(2분 만료)와 별도의 hiking_search_records 문서를 사용합니다.
   '통신두절 대비 자료 공유'에 별도로 동의해야 합니다. 승인된 보호자만 서버 수신 후 최대 24시간 조회합니다.
   '현재 위치 아님'을 표시하며 마지막 GPS 시각/좌표/경로/산행 시작/귀환 예정시간을 제공합니다.
   재전송으로 새 서버 자료가 수신되면 그 수신 시각 기준 최대 24시간입니다.
   보호자 접근 해제는 safety_shares의 기존 viewerUids 목록을 즉시 서버 권한 판단에 사용합니다.
4. 내보내기: 저장된 기록 화면에서 GeoJSON 파일 공유 및 좌표/시각/계획 요약 복사를 제공합니다.
   공유 메뉴에서 파일 저장 또는 필요한 수색 담당자에게 직접 전달하세요. 이미 내보낸 파일은 앱에서 회수하지 못합니다.

복구/종료
앱 재실행 후 산행 시작을 누르면 저장된 기록 이어가기/새 산행 선택이 나옵니다.
GPS 수집과 위치 공유를 몰래 자동 재시작하지 않습니다. 이어가기 후 위치 공유는 다시 동의해야 합니다.
앱 강제 종료, 위치 권한 철회, OS/배터리 제한 중에는 GPS 기록을 보장하지 못합니다. 기록 중단 구간을 복원하지 않습니다.
통신두절 후 새로운 원격 위치를 알아내거나 자동 구조/신고를 하는 기능이 아닙니다.
공유 중지/산행 종료 시 수색 서버 문서를 삭제하도록 대기 작업을 저장하고 재시도합니다.
오프라인에서는 서버 삭제와 보호자 권한 해제의 반영이 늦어질 수 있습니다. 기존 자료는 만료 전까지 조회될 수 있습니다.
기기 자료는 종료 뒤에도 내보내기를 위해 남으며 '기기 기록과 서버 자료 삭제'로 지웁니다.
다른 계정으로 로그인하면 해당 계정 기록만 앱에서 불러옵니다. 기기 저장소 자체 암호화 기능을 새로 추가한 것은 아닙니다.

Firebase 규칙: 이번에는 추가 반영이 필요합니다.
기존 규칙 전체를 지우지 마세요. SEARCH_RULES_V19.txt의 match /hiking_search_records 블록을
match /databases/{database}/documents { ... } 안에, 다른 최상위 match 블록 옆에 추가하고 게시하세요.
기존 signedIn(), owner(), companionVerified()와 V1.7 보호자 규칙은 유지합니다.
이미 같은 경로 규칙이 있다면 중복 추가하지 말고 해당 블록만 교체하세요. 규칙은 여러 match가 허용을 합산합니다.
firestore.companion.merged.rules는 과거 제공해주신 전체 규칙에 V1.7과 V1.9를 합친 참고본입니다.
그 이후 콘솔에서 변경한 규칙이 있다면 전체 참고본으로 덮어쓰지 마세요.
서버에는 아직 게시하지 않았습니다. Firebase 프로젝트가 orqube-576e7인지 확인하세요.

24시간은 읽기 권한 만료입니다. Firestore에서 물리적으로 자동 삭제하려면 추가 설정이 필요합니다.
Firebase/Google Cloud의 Firestore TTL 정책에서 collection group hiking_search_records, timestamp field retainUntil을 설정하세요.
TTL 삭제는 즉시 실행되지 않을 수 있지만 위 규칙은 기한 만료 즉시 보호자 읽기를 차단합니다.
TTL은 이 ZIP이나 규칙 게시만으로 활성화되지 않습니다. 계정 소유자는 삭제 전 자기 문서를 읽을 수 있습니다.

기기 테스트 순서
A/B 다른 계정으로 이메일 인증 → B 연결 요청 → A 승인.
A 산행 시작 → 귀환 예정시간 확인 → 위치 공유 → 수색 자료 공유에 별도 동의.
A 실제 이동 후 '저장된 기록과 내보내기'에서 좌표와 시간 확인.
B 상대 위치 확인 → '마지막 산행 기록 · 수색 참고자료'에서 기록 확인.
A 데이터 통신을 끄고 GPS는 켠 채 이동 → 기기 기록 증가 확인.
B 실시간 지도 만료 후 수색자료의 마지막 시각과 좌표가 그대로 남는지 확인.
A 연결 복구 → 전송 대기 해소 → B 경로와 마지막 GPS 시각 갱신 확인.
A 화면 재실행 → 기록 이어가기 확인. 강제 종료 중 빈 구간이 새 기록처럼 만들어지지 않는지 확인.
GeoJSON 공유 후 외부 지도 프로그램에서 경도/위도 순서 및 관측 시각 확인.
A 공유 중지/산행 종료 → B 문서 숨김 확인. A 보호자 해제 → B 접근 거부 확인.
미승인 C 계정으로 직접 문서 읽기/전체 목록 조회/다른 UID 쓰기가 거부되는지 확인.
자료 공유 거절 시 B는 수색자료를 읽을 수 없고 기존 실시간 공유만 가능한지 확인.
오프라인 공유 중지 → 앱 재실행/연결 복구 후 삭제 재시도 확인.
안심귀가에는 새 산행 수색자료가 생성되지 않는지 확인.

Dart 문법 파서와 파일 구조/ZIP 검사를 수행합니다.
