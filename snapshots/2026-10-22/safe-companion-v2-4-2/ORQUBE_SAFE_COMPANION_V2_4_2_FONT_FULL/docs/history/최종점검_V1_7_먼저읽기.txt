실행
이전 Flutter 실행 창 Ctrl+C 후 새 폴더에서:
flutter pub get
flutter analyze --no-fatal-infos
flutter test
flutter run -d chrome --web-port=7354
로그인 저장을 유지하려면 같은 브라우저/포트를 사용합니다.
최초 안내 동의가 이미 저장되어 있으면 다시 표시하지 않습니다.
동의 화면 색상 테스트는 위 flutter test로 확인하거나 별도 브라우저 프로필에서 확인하세요.

APK
powershell -ExecutionPolicy Bypass -File .\BUILD_TEST_APK.ps1
생성 경로: build\app\outputs\flutter-apk\app-debug.apk
테스트 전용 APK입니다. 휴대폰 설치 후 권한/로그인/App Check를 실제 확인해야 합니다.
디버그 APK는 App Check debug provider를 사용합니다. 실행 로그의 디버그 토큰을 Firebase Console → App Check → 해당 Android 앱 → 디버그 토큰에 등록해야 합니다. 토큰은 공개하거나 공유하지 마세요. 운영 release는 Play Integrity를 사용합니다.
Google Play 제출용은 업로드 키 설정 후 별도의 release AAB가 필요합니다.

필수 두 휴대폰 확인
1. 양쪽 로그인/메일 인증 완료.
2. A ID를 B에 전달 → B 요청 → A가 B ID 확인 후 승인.
3. A 산행 시작 → 공유 동의 → B 위치 확인 → 실제 이동 시 지도 동선/수신시간 확인.
4. A 공유 중지 → B 조회 거부 확인. 다시 시작 후 A가 B 해제 → 조회 거부 확인.
5. 안심귀가에서도 같은 절차, 목적지/귀가 완료와 종료 확인.
6. GPS 거부/인터넷 단절/화면 꺼짐/절전/앱 종료를 별도로 확인.
현재 백그라운드 연속 공유와 자동 지연 알림은 출시 검증이 끝난 기능이 아닙니다.

검증 범위
제작 환경에 Flutter/Dart/Android SDK가 없어 flutter analyze/flutter test/APK 빌드는 실행하지 못했습니다.
Dart 구분자/파일 연결/6개 언어 사전/규칙 원본 보존/ZIP 검사만 수행했습니다.
테스트 코드는 동의 버튼과 밝은 테마, 실행 중 언어 변경/저장을 검증하도록 포함했습니다.
실제 기기 통과본/정식 출시 최종 승인본으로 표기하지 않습니다.
기존 지도 상세 문구는 영어/한국어가 남을 수 있어 다국어 QA가 더 필요합니다.
