# 공개 자료 관리와 점검 현황

기준일: 2026-10-26

## 공개 기준

공개 저장소에는 서비스 소개, 공개 가능한 개발 이력, 사용자 설명서와 검토한 예제만 등록한다.
운영 서버 소스, 핵심 알고리즘, 내부 사업 자료, 관리자 식별 정보, 인증정보는 비공개 보관 대상으로 검토한다.
공개 저장소의 폴더나 브랜치에 비공개 표시를 붙이는 것만으로 접근을 제한할 수 없다.
비공개 자료는 별도 비공개 저장소에 보관하고 공개 저장소에는 검토한 자료만 반영한다.

## 이번 조치

운영 소스를 공개 저장소로 가져오던 자동 가져오기 스크립트를 중단했다.
일반 개발 기록과 공개 저장소 자체는 유지한다.
기존 파일과 과거 커밋의 자료는 아직 제거하지 않았다.

## 점검 범위와 한계

점검 시 확보한 main 브랜치의 18개 커밋, 716개 고유 파일 내용에 대표적인 비밀키·인증 토큰·비밀번호 대입 형식 검사를 수행했다.
대표 키 형식에서 운영 자격증명을 확정할 만한 항목은 발견되지 않았다.
복구문구·비밀번호 관련 검색 결과 일부는 테스트 파일에서 나왔으며 실제 운영 자격증명 여부를 전부 확정한 것은 아니다.
이 결과는 민감정보가 전혀 없다는 보증이 아니다. 사업상 비공개 범위는 패턴 검색으로 판단할 수 없다.
첨부 이미지의 문자, 연결 사이트, 공급 서버의 공개 자료, 외부 복제본까지 점검한 것은 아니다.

## 남은 조치

- 비공개 보관 저장소와 접근 권한 준비
- 기존 소스와 운영 자료의 비공개 원본 보존 확인
- 공개할 문서와 예제만 선별
- 공개 이력에 남은 비공개 대상의 제거 방법 결정
- 실제 자격증명 노출이 확인되면 발급처에서 폐기·교체
- 사이트가 배포하는 원본 소스 묶음의 공개 범위 별도 검토
- GitHub Issues·댓글·워크플로 로그와 외부 복제본 범위 추가 확인

일반 파일 삭제 커밋만으로 과거 이력의 내용은 제거되지 않는다.
과거 이력 정리와 비공개 저장소 준비가 끝나기 전에는 비공개 전환 완료로 표시하지 않는다.
