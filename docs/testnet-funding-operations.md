# 테스트 코인 수령·적립 운영 설명서

작성일: 2026-10-26 (한국시간)
상태: 설계 초안 / 미구현 / 운영 검증 전
관련 계획: [Issue #1](https://github.com/Orqube/orqube-development-archive/issues/1)

## 문서 관리 원칙

개발 계획과 할 일, 진행 상태는 GitHub Issues에 기록합니다.
기능 설명과 운영 절차는 docs 폴더에 기록합니다.
구현·테스트·배포 완료는 실제 확인한 근거가 있을 때만 표시합니다.
이 문서 등록만으로 사이트가 수정되거나 자동 수령 작업이 활성화되지는 않습니다.
모든 채팅이 자동 기록되는 기능을 설정한 것은 아닙니다.

## 목적과 범위

오르큐브 운영 지갑이 테스트용 네이티브 코인을 주기적으로 받아 비축하고, 향후 사용자 테스트 지갑에 공급할 기반을 준비합니다.
운영 지갑의 수령·비축이 이번 계획의 핵심이며 사용자별 자동 지급은 후속 구현 범위입니다.
메인넷 실제 자산의 구매·수령·송금은 이 루틴에 포함하지 않습니다.
직접 발행한 테스트 토큰과 거래 수수료에 쓰는 테스트용 네이티브 코인은 구분해서 관리합니다.

## 대상과 준비 상태

| 대상 | 테스트 환경 | 운영 수령 지갑 상태 |
|---|---|---|
| KAIA | Kairos를 후보로 검토 | 기존 지갑의 운영용 사용 가능 여부와 소유권 확인 필요 |
| Polygon | Amoy를 후보로 검토 | 사용자가 지갑 준비 예정 |
| Solana | Devnet을 후보로 검토 | 사용자가 지갑 준비 예정 |

네트워크·RPC·자산 명칭 및 공급처의 현재 지원 여부는 구현 전에 공식 자료로 확인합니다.
수령 주소는 아직 확정하지 않았으며 이 문서에는 운영 주소나 인증정보를 기재하지 않습니다.
이전에 울림에 등록한 사용자 지갑과 운영 지급 지갑이 같다고 가정하지 않습니다.

## 계획된 실행 흐름

1. 일일 실행 시각을 한국시간 기준으로 설정합니다. 정확한 시각은 미정입니다.
2. 체인별 네트워크와 수령 주소, 공급처 설정을 확인합니다.
3. 잔액·최근 수령 기록·다음 신청 가능 시각·공급처 한도를 확인합니다.
4. 자동화가 허용된 공급처의 공식 경로로만 신청합니다.
5. 요청 접수 상태를 저장하고, 거래 확인 또는 공급처 증빙을 통해 실제 입금을 별도로 확인합니다.
6. 확인된 수령 건만 적립 이력에 반영합니다. 잔액 증가는 다른 입금일 수도 있으므로 잔액 변화만으로 동일 수령 건을 확정하지 않습니다.
7. 실패 사유와 다음 재시도 가능 시각을 기록하고 관리자 화면에 표시합니다.

## 자동화 허용 범위

공급처별 API 제공 여부, 자동화·재분배 허용 조건, 신청 간격, 일일 한도와 보유 잔액 제한을 먼저 확인합니다.
CAPTCHA나 수동 인증이 필요한 공급처는 관리자 수동 충전 절차로 분리합니다.
인증·한도 우회나 다중 계정으로 제한을 피하는 처리는 구현하지 않습니다.
공급 중단이나 정책 변경이 있을 수 있으므로 매일 지급이나 무제한 누적을 보장하지 않습니다.

## 중복과 실패 처리

체인·공급처·수령 주소·신청 주기를 기준으로 동시 실행을 차단합니다.
확인된 거래 식별자 또는 공급처 수령 식별자로 중복 적립을 막습니다.
네트워크 시간 초과 시 이전 요청의 처리 여부를 먼저 조회한 후 재신청합니다.
인증 필요, 한도 초과, 공급 중단, 입금 확인 지연, 잘못된 네트워크를 구분해 표시합니다.
장애 알림 채널과 재시도 정책은 구현 단계에서 정합니다.

## 기록 항목

실행 시각, 네트워크, 공급처 식별자, 수령 주소 참조, 요청 식별자, 요청 상태, 확정 수령량, 거래 식별자, 확인 시각, 잔액, 실패 사유, 다음 신청 가능 시각을 운영 저장소에 남깁니다.
실제 운영 로그와 설정은 이 공개 GitHub 저장소에 올리지 않습니다.

## 지갑과 비밀정보

받기 전용 작업에는 공개 주소를 사용합니다. 개인키나 복구문구를 사용자에게 요청하지 않습니다.
향후 사용자에게 보내는 작업에는 별도 서명 권한 설계가 필요하며 수령 작업과 분리합니다.
개인키·복구문구·인증 토큰·운영 설정은 코드, Issues, docs, 실행 로그에 기록하지 않습니다.

## 검증 후 활성화

- 공급처의 자동 수령 및 서비스 사용 허용 조건 확인
- 테스트 네트워크와 수령 지갑 확인
- 실제 테스트 코인 수령 및 거래 확인
- 중복 실행·재시작·입금 지연·한도 초과 처리 확인
- 비밀정보가 문서와 로그에 포함되지 않는지 확인
- 검증 결과를 Issue #1에 기록하고 운영 활성화 여부 명시

현재는 계획과 설명서만 등록된 상태입니다.
