# 개발·운영 문서 작성 기준

등록일: 2026-10-26

## 기록 위치

- Issues: 개발 계획, 오류, 개선 요청, 진행 상태와 완료 근거
- docs: 서비스 설명, 확정 정책, 사용법, 배포·운영 절차
- history: 버전별 변경 사항과 개발 이력
- snapshots: 확보한 소스의 시점별 보관본

## 문장과 구성

업무 담당자가 읽고 바로 판단할 수 있도록 짧고 구체적으로 작성한다.
결정 사항, 변경 이유, 적용 범위, 확인 결과, 남은 작업을 중심으로 기록한다.
과장된 홍보 문구, 불필요한 감탄, 반복되는 상투적 표현, 대화체 진행 보고는 제외한다.
제목과 용어를 일관되게 사용하고 기술 설명은 운영과 검토에 필요한 수준으로 적는다.

## 사실과 상태

계획, 구현, 테스트, 배포를 구분한다. 요청이나 과거 답변만으로 완료를 확정하지 않는다.
검증 결과는 확인한 환경과 근거를 함께 남긴다.
과거 작업일과 실제 문서 등록일을 구분하고 확인되지 않은 날짜는 추정으로 표시한다.
작성 방식이나 도구에 관한 불필요한 문구는 넣지 않되 작성자·기여 내역을 허위로 표기하지 않는다.
기존 저작권, 라이선스, 필수 고지는 유지한다.

## 이전 자료 정리

기존 연대표와 소스 보관본을 유지하며 부족한 최신 설명서를 보충한다.
서비스별 설명서, 확정된 기능과 요금 정책, 배포 방법을 우선 정리한다.
백서와 사업계획서는 공개 가능한 최신본을 선별한다.
오래된 자료를 보관할 때에는 적용 시점과 현재 유효 여부를 명시한다.
중복 자료와 초안은 최신 운영 기준과 혼동되지 않도록 구분한다.

## 공개 제외

개인정보, 지갑 복구문구·개인키, 비밀번호, 인증 토큰, 비공개 운영 설정은 공개 저장소에 기록하지 않는다.
상세 공개 범위는 [공개 등록 범위](../PUBLICATION_SCOPE.md)를 따른다.

## 현재 등록 범위

이 문서는 기록 방식과 작성 기준을 정한 것이다.
이전 문서 전체의 재정리나 운영 사이트 변경을 완료했다는 의미는 아니다.
테스트 코인 수령 계획은 [Issue #1](https://github.com/Orqube/orqube-development-archive/issues/1), 설명서는 [테스트 코인 수령·적립 운영 설명서](testnet-funding-operations.md)에서 관리한다.
