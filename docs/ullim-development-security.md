# 울림 · 울림 한글 개발 및 보안 현황

기준일: 2026년 11월 5일 · ORQUBE

오르큐브는 울림을 소통과 문서 작업을 함께 할 수 있는 공간으로 개발하고 있습니다. 우리는 기능 구현, 실제 확인 결과, 앞으로 확인할 과제를 구분해 기록합니다.

## 개발 과정

1. **문서 읽기·편집** — HWP 등 기존 문서를 불러와 글을 복사하고 수정하는 기능에서 시작했습니다.
2. **그림·표 지원** — 그림 추가·크기 조절, 표의 행·열 편집과 셀 병합, 실행 취소·다시 실행을 확장했습니다. 복잡한 원본 배치와 일부 개체는 달라지거나 누락될 수 있습니다.
3. **울림 한글** — 한글·영문 혼합 작성, 문서 전체 글꼴·크기·굵기·정렬·줄 간격, 기본 단어의 한자 후보 선택을 제공합니다. 선택 영역별 서식이나 모든 단어의 한자 변환을 지원하는 단계는 아닙니다.
4. **전용 문서 저장** — 글·그림·표와 문서 전체 서식을 `.ullim`으로 저장하고 다시 엽니다. 일반 저장과 비밀번호를 사용하는 암호화 저장을 구분합니다. HWP·DOCX 등 호환 내보내기는 새 문서 전체 서식을 모두 보존하지 않습니다.
5. **글꼴·인쇄** — 원본 획으로 제작한 ‘울림 바탕·울림 돋움’ 보통 굵기 시안을 제공하고, 현재 편집본의 인쇄 미리보기와 브라우저 인쇄/PDF 저장을 연결했습니다. 글꼴은 아직 가독성과 인쇄 품질을 다듬는 개발 시안입니다.
6. **첫 화면 정리** — 문서 편집기와 보안 확인을 앞에 배치하고, 이벤트·스테이킹은 별도 공간으로 분리했습니다. 모임은 ‘모임 · 만들기’ 메뉴에서 이용합니다.

## 적용한 보안과 공개 확인

| 항목 | 현재 상태 |
| --- | --- |
| 문서 처리 | 편집 문서를 서버에 자동 업로드하지 않고 브라우저에서 처리합니다. 사용자가 공개 게시물에 직접 올리는 내용은 별도입니다. |
| 실행·요청 제한 | 편집기의 코드 실행·외부 통신 제한, 비정상 요청과 과도한 반복 요청 제한, 보안 헤더와 주요 의존성 업데이트를 적용했습니다. 호스팅 방화벽 전체를 대신하지는 않습니다. |
| 로그인 정보 | 서버에 저장하는 로그인 토큰에 암호화를 적용했습니다. 기존 기록의 순차 전환이 모두 끝났는지는 별도 확인 대상입니다. |
| 문서 암호화 | 암호화 저장은 AES-256-GCM을 사용합니다. 일반 `.ullim`과 호환 형식 저장은 암호화되지 않습니다. 비밀번호를 잊으면 복구할 수 없습니다. |
| 사용자 확인 | [보안 확인 페이지](https://ullim.orqubic.com/security)에 SSL Labs·SecurityHeaders 검사 링크와 적용·미확인 항목을 공개했습니다. 외부 검사 등급을 확인·인증했다고 표시하지 않습니다. |
| 추가 확인 | 양자내성 TLS의 실제 적용, 관리자 다중 인증, 호스팅 방화벽의 상세 범위는 아직 확인이 필요합니다. 독립 기관 침투 테스트도 미실시입니다. |

우리는 암호 방식의 향후 교체를 고려한 구조를 마련했지만, 사이트 전체의 양자내성 보안이 완성됐다고 주장하지 않습니다. 기기나 사이트 자체가 장악되면 열어 둔 문서가 읽힐 수 있으며, 독립 블록체인도 이 위험을 자동으로 없애지는 못합니다.

## 확인한 범위와 남은 작업

- 파일·DOM 검사에서 한글/영문, 그림·표, 일반·암호화 ULLIM 저장과 복원, 한자 후보 선택·실행 취소를 확인했습니다. 관련 빌드와 배포가 성공했습니다.
- 운영자의 실제 사용으로 인쇄 미리보기 표시를 확인했습니다. 실제 프린터 출력과 모든 브라우저·Windows 기기의 호환성을 검증했다는 뜻은 아닙니다.
- 외부 검사 점수는 일부 공개 설정의 결과이며, 내부 접근 권한이나 모든 유출 가능성을 보장하지 않습니다.
- 다음 과제는 글꼴 품질 보정, 선택 영역별 서식, 한자 사전 확대와 운영 보안 설정의 확인입니다.

이 문서는 공개 가능한 개발 요약입니다. 전체 소스 보관본은 별도로 관리하며 개인정보·비밀키·인증 토큰·비공개 운영 설정은 공개하지 않습니다. 기존 구성요소의 라이선스와 필수 고지를 유지합니다.
