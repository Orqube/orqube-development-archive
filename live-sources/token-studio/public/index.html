전문 계약 설계

선택한 옵션을 그대로 저장합니다. 배포 서버의 옵션 지원이 확인되기 전에는 단순 고정형 계약으로 바꿔 배포하지 않습니다.

초안을 검토·수정하고 발행량을 직접 입력한 뒤 적용합니다. 적용 → 선택 체인 지갑 연결 → 발행 → 결과 확인 순서입니다. 솔라나는 별도 발행 패널을 사용합니다. 폴리곤은 별도 발행 패널에서 발행 후 Sourcify 소스검증을 자동 요청합니다. 카이아의 현재 유료 검증 서버는 Kaia 메인넷 계약을 대상으로 하며, 테스트넷 토큰이 메인넷으로 자동 전환되지는 않습니다.

로그인 후 입력 내용은 유형별로 이 기기에 임시 보관합니다. 계정 서버 저장 완료와는 별개입니다.

SOLANA · SPL TOKEN

솔라나 메인넷 · 정식 토큰 발행

신규 솔라나 프로젝트는 메인넷 정식 발행이 기본입니다. 메인넷 SOL로 네트워크 수수료와 계정 보관 비용을 지불하며, 발행 전 예상 비용을 확인합니다. 밈코인·업종형·전문형 모두 같은 SPL 발행 기반을 사용합니다. 최초 수량은 연결 지갑에 발행하고 추가 발행 권한을 폐기합니다. 보유자는 자신의 토큰을 소각할 수 있습니다. QR 보상·운영 계획은 별도 서비스입니다.

오르큐브 내 지갑은 일반 브라우저에서 암호화 비밀번호로 승인합니다. 외부 지갑은 해당 앱의 브라우저에서 연결하세요. 기존 지갑 복구문구 입력은 요청하지 않습니다.

RPC는 선택한 Devnet 또는 Mainnet과 일치해야 합니다. 입력값은 이 기기에서만 사용합니다.

이름·심볼은 온체인 메타데이터에 기록합니다. 외부 지갑의 로고·소개 표시에는 image 필드가 포함된 영구 공개 JSON 주소가 필요합니다. 기본 도형 로고 미리보기만으로 외부 지갑에 자동 등록되지는 않습니다.
